# 介面 PR 截圖與視覺審查備查規範

本文件是介面變更截圖交付的單一規範來源，由 [AGENTS](../AGENTS.md)、UI 開發及 PR 作者／審查技能共同引用。自本規範引入起，所有介面調整 PR 都必須提供實作截圖，在 PR Body 展示改動，並保存可追溯的視覺審查證據。

## 適用範圍

包含桌面／網頁／Companion 頁面、設定表單、導覽、對話框、主題、響應式版面、會影響呈現的文案、HUD／Canvas／SVG 樣式，以及互動造成的可見狀態變化。介面重構即使聲稱外觀不變，也須提供截圖作為確認依據；不能只依副檔名或是否修改 CSS 判定。

純文件、純後端或其他不影響使用者可見介面的 PR 可註明「無介面變更」，不必製造無關截圖。混合 PR 仍須覆蓋其中的介面變更。

## 必交內容

1. **PR Body 直接展示**：加入「Visual Review／視覺審查」或同義區塊，以 Markdown 圖片或 HTML 圖片嵌入實作後的畫面，附簡短說明對應變更。大量圖片可用表格或 details 分組，但不能只留下本機路徑、測試成功文字或未嵌圖的下載連結。
2. **變更覆蓋**：每個受影響頁面／分頁與主要變更狀態都要有可辨識的畫面。新增多款 HUD、音響、圖表或其他視覺樣式時，每款至少一張並逐項標名，不能用其中一款代表全套。涉及展開／收合、焦點、停用、錯誤等呈現時，補足受影響狀態。
3. **主題與尺寸**：依下表選取代表圖並記錄完整檢查範圍，不必把所有測試組合逐張貼滿 Body。適用範圍內不得只展示預設主題；不支援某主題或尺寸時說明原因。
4. **保存備查**：圖片與紀錄放在適當的 `docs/<領域>/...`、既有圖集，或可由審查者持續存取的 PR 附件。Body 連到完整證據；repository 圖片優先以 commit 固定連結，避免分支推進後無法確認審查的是哪一版。不得只存於會消失的 scratch 或已知會到期的 CI artifact。
5. **版本同步**：截圖須符合最新介面實作。後續改到呈現時重拍受影響畫面並更新 Body／證據索引；若後續只改文件或與介面無關的內容，可沿用，須註明擷取版本及與目前 head 的介面相同。不得把舊版圖標為新版。

## 視覺覆蓋矩陣

| 變更範圍 | 截圖與備查要求 |
| --- | --- |
| 跨設計系統的共用介面 | 在 Halfmoon、Swiss、Rhine 各選代表 core，提供受影響畫面的日／夜截圖；其餘支援 core 的檢查結果記入備查。 |
| 特定主題或平台專屬介面 | 提供受影響主題／平台的畫面與適用模式，並說明其他系統不適用的範圍。 |
| 支援響應式的桌面頁面 | 包含預設 1280×720 與 320px 窄幅代表圖；其他支援尺寸、寬視窗與 overflow 檢查記入備查。Companion／原生行動頁採實際支援尺寸並記錄。 |
| 多語文案或排版變更 | 檢查繁中／英文／日文；翻譯長度、換行或字形是變更重點時，附各語系代表圖，其餘以紀錄列出覆蓋。 |
| HUD／Canvas／獨立視覺元素 | 每款以實際 launcher／renderer 擷取，記錄 scale、DPR、背景與輸入資料；可採元素裁切，但須標明，不能用素材原圖代替執行結果。 |
| 動畫或動態狀態 | 截圖仍必交；必要時另附短片或狀態序列，記錄 reduced motion 檢查。靜態圖不能證明動畫、效能或高更新率表現。 |

## 擷取真實性與證據紀錄

- 頁面截圖應使用實際應用程式容器、導覽及主題 providers，保留正式留白與樣式作用域。隔離元件圖可作補充，不能取代整頁樣式整合證據。
- 使用可重現、無敏感資訊的資料。不得為了截圖掩蓋問題而隱藏工具列、覆寫產品排版、修圖或以設計稿／生成圖片冒充實作。透明 HUD 可使用中性背景，但須註明；裁切或必要遮罩亦需揭露，且不得遮住受審查內容。
- 每組圖在 Body、圖集 README 或 manifest 記錄：擷取日期、程式碼版本（commit 或明確的 base 加未提交改動說明）、平台／瀏覽器或原生環境、viewport、語系、主題／模式、相關設定與資料來源。另提供重現入口（腳本或操作步驟）、檢查結果及未涵蓋範圍；多圖共用條件可集中列出。
- 若附 before／after，分別標示版本與狀態，盡量維持相同主題、尺寸、語系及輸入，避免把環境差異當成變更效果。
- 作者需實際檢視產出的圖片，確認改動可見、文字／字形／對齊／裁切／overflow 沒有異常，再將可用圖片納入 Body。發布後讀回並確認嵌圖與連結可用。

## 交付與審查邊界

截圖是介面 PR 的必要交付物，不能以 Vitest、build、CI 綠燈或 DOM 斷言取代。Reviewer 依變更逐項核對圖片、版本、覆蓋與備查；缺圖、過期圖或無法存取須列為待補交付，不宣稱視覺審查已完成。

瀏覽器 fixture、模擬音訊／遙測、離線 renderer、原生程式、真實裝置及遊戲截圖須明確區分。視覺審查不等同遊戲、原生跨螢幕、實體裝置或 Narrator／NVDA 驗收。環境限制導致無法擷取時，記錄缺項、原因與剩餘工作，仍屬未完成的截圖交付，不得用虛構或不相符圖片補足。

純文件後續提交只需檢查規範連結、版本聲明與格式；相關介面未變時不強制重跑產品測試或重拍。本規範不新增每個樣式的微觀像素單元測試；瀏覽器驗證仍依 [testing-strategy.md](testing-strategy.md) 與純函式測試分開執行。
