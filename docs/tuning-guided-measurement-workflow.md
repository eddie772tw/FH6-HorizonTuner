# 指引式調校資料準備工作流

更新：2026-09-10。此文件描述 `codex/chassis-sevenlap` 的資料準備流程；一般使用者不需要先知道理想極速、換檔點或指定 RPM。整體導覽已改為六階段，工程依據與計算依賴見[工作流規劃](tuning-workflow-dependencies-20260910.md)。

## 使用順序

1. **確認靜態資料**：選擇用途，填寫目前改裝車輛可查的重量、前軸配重、馬力與扭力，確認驅動方式、輪胎與檔數。既有 profile 包含預設值，不能把它們當成遊戲自動讀取結果；重量、配重有效即可先看輪胎、底盤與定位。馬力有效才可收集引擎資料。空力套件、下壓力與空力效率暫不參與一般算牌，不要求玩家輸入或猜測。
2. **建立機械基準與啟動引擎資料準備**：儲存後先查看輪胎基準、底盤平台及定位；這是建議順序，也可直接開啟「動力與傳動」（第 5 階段）收集引擎資料。使用既有 Data Out 連線，不啟動全域 dyno/race recording，也不新增 UDP listener。
3. **依提示駕駛**：在空曠直線，從較低轉速開始，以同一檔全油門平順加速至接近引擎上限。可以分數次完成；面板會指出低轉、高轉或中間範圍不足、換檔過渡、資料中斷等問題。滑移顯示為觀測資訊。玩家可暫停、繼續或重新開始。
4. **確認資料完成**：系統需要有效加速時間與轉速範圍同時足夠，不以倒數計時代替品質檢查。首次完成後自動停止更新摘要，玩家可離開遊戲駕駛畫面，再按「下一步：使用收集資料算牌」。也可選「保留資料，繼續收集」追加下一趟，再按「結束追加收集」；返回選單後仍保留最近一次可用結果。達標不代表引擎峰值已穩定，改裝身分或遙測時間重置仍會使保留結果失效。
5. **使用固定資料算牌**：齒比使用靜態 profile 與完成的引擎快照，輪胎／底盤／定位直接使用同一份靜態資料。即時遙測及背景 dyno polling 不會持續重設這份算牌。未完成引擎準備只限制齒比與第 6 階段整套驗證，不鎖住機械頁面。

## 輸入來源與用途

| 輸入 | 來源 | 用途／限制 |
|---|---|---|
| 車重、配重、馬力、扭力、驅動、輪胎、檔數與可調範圍 | 玩家確認的本機車輛 profile／遊戲靜態資料 | 保留原值；不以瞬時馬力覆寫遊戲規格。profile 內的預設值不等於偵測結果。 |
| 引擎轉速上限 | 本次有效遙測 `EngineMaxRpm` | 供齒比運算與圖表；基本流程不再要求手填或使用 peak-HP RPM × 1.15 猜測。 |
| 已觀測功率與扭力峰值的 RPM | 本次全油門有效引擎樣本 | 補齊 `maxHpRpm`／`maxTorqueRpm`；只代表本次樣本中的峰值，不保證捕捉到完整引擎曲線真實峰值。 |
| 車型、級別、性能指數 | `CarOrdinal`／`CarClass`／`CarPerformanceIndex` | 防止跨車或跨性能段混合；不是完整零件 fingerprint。 |
| 車速 | 不用於此階段目標推算 | 瞬時車速及一次 run 的最高車速不自動當成理想極速。 |
| 空力、抓地等模型係數 | 原有模型假設 | 本次沒有由短時間加速推算這些量；仍不是 FH6 已校準常數。 |

## 目前品質門檻

這些是量測完整性 heuristic，不能解讀為 FH6 最佳調校數值：

- 使用既有 WebSocket 的逐筆解碼封包更新量測狀態，React 約 5 Hz 發布顯示摘要，保留最多 16 個轉速區間摘要；不保存完整逐幀 capture，實際接收頻率取決於來源。
- 只接受同車、完整 identity、`IsRaceOn = 1`、有限且向前遞增的 timestamp；紅線或 identity 改變、timestamp 倒退需重新收集。
- 全油門輸入至少 250/255，煞車／手煞車／離合器輸入均明確為 0；前進檔為整數 1–10；功率、扭力與 RPM 必須為有限正值。
- 換檔後 500 ms 的輸出過渡不接受。輪胎 normalized slip 只保留觀測最大值，不作為引擎功率／扭力拒收條件；缺失時不生成滑移摘要。這不代表可用同一批資料驗證路面抓地或輪胎有效周長。
- 相鄰有效樣本累積至少 6 秒。超過 1 秒的中斷、拒收樣本、手動暫停與換檔過渡不累加。
- 至少覆盖紅線的低端 40% 以下、高端 90% 以上，且 16 個區間中至少 8 個有有效資料；缺少任一條件就提示仍需補哪種駕駛資料。
- 收集中若 timestamp 兩秒沒有進展，資料過期；連線開著不能單獨證明遙測仍更新。

達標後保留的是「已完成收集的快照」，所以離開遊戲或暫停不會把完成狀態清掉。若遊戲重新回報不同車、級別、PI 或紅線，則要求重新收集。更换同 PI 的零件無法完全自動辨識，畫面會提醒重新收集。

## 快照生命週期與進階模式

- 點擊下一步才將完成的量測與當時靜態 profile 一起固定；計算前不把部分量測混入正式算牌。
- 換車、修改任一靜態 profile 欄位、重新收集會使先前快照失效；背景 `dyno_curve`／`dyno_quality` 更新不會使其失效。此快照目前只在頁面生命週期內保留，離開／重新載入需重新準備。
- `CarParamsContext.loadedCarId` 防止切車時讀到上一台車尚未替換的 profile；取消後的舊 dyno poll 回應不會合併進新車。
- 預設 `automatic` 模式忽略既有自訂速度、指定 RPM 與 legacy cap，即使舊 preset 還存有這些數字也不會偷偷套用。要測試自訂目標或舊版校正，必須在進階齒比選項明確選擇模式。
- 底層 `calculateAEGOGearing` 的舊介面保留相容；Drag／Drift 前四檔等既有 profile 假設仍在。本輪改的是輸入資料工作流，沒有宣稱完成 Drag meta 或每車 gearbox capability 校準。

## 驗證範圍

純狀態機測試涵蓋：完整 sweep、缺少轉速區間、停滯／倒退時間、断線、錯車、PI／紅線改變、非有限或缺失控制、打滑、量測中斷、換檔過渡、鬆油門後使用完成資料。AEGO 測試涵蓋預設模式不採用舊進階輸入，以及自訂目標的顯式選用。

狀態機與建置驗證不等於引擎峰值精度驗證。Integra A700 已完成一般資料準備、候選套用及三場基準／三場候選的真實 ANNA 比較，見 [綜合比較](integra-a700-comprehensive-comparison.md)；不能據此宣稱全車型公式已校準。新追加收集操作的狀態保留、更新與失效測試通過，完整前端 95 files / 645 tests 與 TypeScript/Vite build 通過；此新操作的完整實機驗收仍待完成。高精度性能比較仍需完整 capture／dyno 流程與受控 A/B 驗證。

初始實作自動驗證：90 files / 610 passed；TypeScript、Vite、後端 268 passed / 8 deselected、Ruff 通過。後續真實 ANNA 驗證、門檻修正及重新驗證狀態見 [實測紀錄](tuning-live-validation-plan.md)。未新增第三方依賴或修改 UDP layout。

## 真實資料後的單位與滑移修正

2026-09-09追加收集實機驗收：193200記錄對應的北部環道Forzab場，首次ready時6.0秒／14區間，點追加後先觀察52.8秒、賽後96.3秒；返回賽後畫面仍能結束追加並算牌。新摘要圖示功率峰值約6501.75 RPM、扭力峰值3088.31 RPM，終傳3.89，尚未套用此新齒比。完成只證明資料生命週期可操作，峰值穩定性仍需檢查。DEV已載入語系沒有自動更新，所以新增文字顯示英文；磁碟繁中翻譯已存在。驗收找到追加期間ready提示誤稱可直接下一步，已修正為先結束追加；補點擊時最新狀態檢查，目標16 tests及build通過。

既有 profile 與 dyno import 的 `maxTorque` 儲存單位為 lb-ft，車輛參數與精靈顯示需一致；只在 solver 邊界轉換為 Nm。347 lb-ft 對應 470.46954 Nm，不修改持久化資料格式。

初始 0.1 滑移門檻是未校準假設，已從引擎資料接受路徑移除。北部 ANNA 4490 幀中，符合其餘基本條件的 3195 幀均無法通過 0.1，但引擎 P/T/RPM 同一性仍良好。這支持分開引擎讀數與道路牽引驗證，不支持新的泛用輪胎門檻。

[Forza Motorsport 官方 Data Out 說明](https://support.forzamotorsport.net/hc/en-us/articles/21742934024211-Forza-Motorsport-Data-Out-Documentation) 使用 normalized slip，不能直接等同物理滑移百分比；該文件不是 FH6 輪胎校準證據。[MathWorks 輪胎模型](https://www.mathworks.com/help/sdl/ref/tiremagicformula.html) 則以接地速度差及縱向速度定義物理滑移，力與滑移關係還受輪胎參數和載荷影響。兩種數值不可直接混用。
