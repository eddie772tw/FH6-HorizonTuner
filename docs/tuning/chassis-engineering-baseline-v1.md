# 底盤工程基準 v1：公式調整定案

日期：2026-10-11。狀態：**已於本機開發分支導入 Rust 產品與桌面流程；實機操控尚未驗證。**

使用者要求是「工程上合理的可用起點」，不追求最優解。本文件為後續實作準據，取代 [初輪評估](chassis-spring-refactor-evaluation-20261011.md) 中仍待選擇的路徑與暫留舊空力係數的建議。使用既有本機分支 `codex/chassis-spring-refactor`，不新增 worktree。採用技能：`physics-tuning-math`、`ponytail`。

## 1. 確定採用的方案

**Road R3 基線＋保留 FWD 偏置；Rally A 基線；共用可選下壓力解析、軸載荷比例彈簧補正，以及隨實際彈簧剛性變動的相對阻尼補正。**

| 項目 | 本次決定 | 理由 |
| --- | --- | --- |
| Road 基礎彈簧 | 採 R3，保留現有 FWD 分支 | 用玩家可見滑桿範圍建立起點，直接移除錯誤空力來源，避免重新調整整套操控偏置 |
| Rally Mixed／Cross | 採 A；總量比例分別固定 0.35／0.48 | 保留原計畫賽事取向，未受限時按配重分配；超限就遵守硬體範圍 |
| Road R1 | 不納入本次 | 固定 6–10% 俯仰偏置沒有行程／幾何依據，且會干擾 FWD 基線 |
| Road R2 | 不納入本次，也不作後備 solver | 缺少每輪簧載質量與運動比，不以新增隱藏輸入作為開發前提 |
| 空力 | 未填可略過；單軸＋明確平衡反推；雙軸直接採用 | 遵循使用者已指定的規則，取消車重 20% 與 drivetrain ratio 推導 |
| 彈簧空力增量 | 改為 `K0 × F / W` | 單位一致、能隨軸重與原始剛性調整，不再固定前除以 20、後除以 50 |
| 阻尼 | 使用已限界的實際彈簧值作平方根相對修正 | 避免彈簧已觸頂，阻尼仍依不可達的目標值持續增加 |
| ARB／車高／差速器／定位 | 沿用既有賽事策略 | 沒有足夠模型理由為這些欄位新增空力係數；本輪集中處理彈簧及其阻尼連動 |

0.35／0.48 與現有 FWD 偏置是**固定的工程起點**，不宣稱是 FH6 最佳常數。這些選擇在本次實作中不再開放多路徑競爭，也不新增三套 Road 模式讓玩家選擇。

本次新公式覆蓋 Road 與 Rally 兩種 profile；Drift、Drag、DangerSign 保留既有模型數值。不能因 Rally 共用 match 區塊而改動 DangerSign。

## 2. 為何這個精度已足夠

絕對自然頻率需要簧載質量、運動比等資料；而實車彈簧選擇本就需要在路面、空力、輪胎、反應與行程間取捨。工程方法允許從有明確假設的基準出發，不必先建立完整車輛模型。[OptimumG：Of Springs and Dampers](https://optimumg.com/of-springs-and-dampers/)、[頻率與運動比公式](https://optimumg.com/wp-content/uploads/2020/01/SpringsDampers_Tech_Tip_2.pdf)。

本方案刻意分成兩層：以遊戲實際滑桿範圍建立**經驗基線**，再以同一輛車的負載／剛性比例進行**有物理依據的相對修正**。Road R3 並不是從第一原理推得絕對剛性；Rally 配重比例亦隱含前後懸吊有效倍率差異不大的粗略假設。這些限制已足以界定適用範圍，不阻止建立可用的第一版。

「合理」的驗收標準是：輸入來源明確、量綱正確、零補正可退回基線、增量方向一致、輸出合法、受限情況可見，以及舊資料可重播。不能把「最快圈速」「不會觸底」或「前彈簧必大於後彈簧」當成通用保證。

## 3. 輸入、單位與可選空力

必要資料為車重 `m`（kg）、前配重 `w`（0–1），以及前後彈簧範圍 `L_i/U_i`（kgf/mm）。新模型要求有限值、`m > 0`、`0 < w < 1`、`0 < L_i <= U_i`。缺少或非法資料時，對應彈簧／阻尼結果標記 unavailable，不使用猜測的範圍生成可套用建議；不相關的底盤欄位可保留各自的資格判定。

下壓力 `F_f/F_r` 使用 kgf。平衡 `b` 定義為前軸占總下壓力的比例，UI 顯示百分比。kgf 是力，不能把下壓力直接當慣性質量。

| 輸入情況 | 解析結果 |
| --- | --- |
| 兩軸皆未填 | 補正用 `F_f=F_r=0`，來源為 omitted；不表示車輛真實空力為零 |
| 僅前軸已填＋明確平衡 | `F_r = F_f × (1-b)/b` |
| 僅後軸已填＋明確平衡 | `F_f = F_r × b/(1-b)` |
| 雙軸已填 | 直接採用；忽略殘留平衡對數值的影響 |
| 單軸已填但缺平衡／無法求解 | 追加要求平衡；完整空力補正結果 unavailable，可另標示未補正基線 |

空白／missing／null 表示未填；新模型保留明確的 0。兩軸皆為明確 0 時不補正，顯示平衡不適用。單軸反推通常要求 `0<b<1`；前已知且 `b=1` 可得後 0、後已知且 `b=0` 可得前 0。反向的除零端點無法唯一反推，必須補另一軸或修正平衡。負值、非有限值、百分比超界與運算溢出均拒絕，不能偷偷更改平衡。

新草稿不得把預設 `aeroBalance=0.5` 當成已填資料。推導值只作為結果顯示，不回寫成玩家輸入；否則下次計算會錯誤走入雙軸已填路徑。舊 Auto=0 與無來源的平衡預設，在轉成新草稿時視為未確認；舊紀錄仍依原版本重播。

空力可調能力與空力負載分開：Fixed／Front Only／Rear Only 不會因反推而解鎖，但有來源的解析負載仍可用於底盤補正。kgf/lbf 只在輸入／顯示邊界轉換。

## 4. 合法範圍與取位

定義 `Q(x,L,U)` 為新模型共用輸出限制。先確保數值有限、範圍有效：

```text
a = ceil(10L) / 10
b = floor(10U) / 10
若 a <= b：Q(x,L,U) = clamp(round1(clamp(x,L,U)), a, b)
若 a > b ：Q(x,L,U) = clamp(x,L,U)
```

一般情況保留既有一位小數輸出；窄區間沒有一位小數可表示時，保留合法精度。例如 `[3.11,3.11]` 必須回傳 3.11；`[3.11,3.14]` 的高於上限目標回傳 3.14。UI 不得再以顯示四捨五入改壞可套用值。此處是輸出精度契約，不宣稱一位小數就是遊戲真實滑桿刻度。

所有 clamp 前保留目標與限制原因。基線受限、空力目標受限和單純取位分開記錄；沒有精確比例解時不做迭代搜尋或補償到另一軸。

## 5. 無空力彈簧基線

令 `w_f=w`、`w_r=1-w`、`Δ_i=U_i-L_i`。`K0_i` 為合法的無空力基線。

### Road：R3，保留 FWD 取向

```text
AWD / RWD：p_f = w_f；p_r = w_r
FWD：p_f = max(0.10, w_f-0.10)；p_r = min(0.90, w_r+0.10)
K0_i = Q(L_i + Δ_i × p_i, L_i, U_i)
```

FWD 的 0.10 是現有工程偏置，保留其來源與可調整性，不加煞車俯仰常數。前後滑桿分別反映各軸可調範圍，不能從輸出數字差距直接推定失衡；本次沒有足夠證據要求 Road 再改成一套新的配重分配模型。

### Rally：A，採兩個固定 profile

```text
s = 0.35（Mixed-Surface）；s = 0.48（Cross-Country）
T = L_f + L_r + (Δ_f + Δ_r) × s
K0_f = Q(T × w_f, L_f, U_f)
K0_r = Q(T × w_r, L_r, U_r)
```

`T` 是此算法的剛性總量指標，不是精確整車輪上剛性。若目標在兩軸範圍內，取位前符合配重分配；若受限，以範圍優先並顯示偏離。**不再調整 T 去追求精確比例**，避免某軸的高下限把另一軸也強行推硬。Cross-Country 對相同輸入的彈簧不低於 Mixed；並不保證落地表現更佳。

## 6. 空力補正：保持基線的相對負載支撐

以前後靜態軸載荷作為可觀測代理：

```text
W_i [kgf] = m [kg] × w_i   （採標準重力，等價 SI 式為 m × w_i × g0）
g_i = 1 + F_i / W_i
Ktarget_i = K0_i × g_i
K_i = Q(Ktarget_i, L_i, U_i)
```

這個修正由 `F=kx` 的相對關係推得：負載增加幾成，就讓剛性增加幾成，維持簡化模型中的支撐尺度。同車同軸的每輪二等分與固定運動比在比例中抵消，因此不必要求玩家猜測運動比。**這是本次工程推導，並非引用來源已驗證的 FH6 公式。**

因使用總軸重代理簧載部分，不能宣稱維持了真實避震下沉量；也不計算速度平方曲線、觸底餘量或空力地圖。輸入下壓力被視為玩家所提供工況的名義負載，同一對輸入應來自一致的工況／定義。本次不追加無資料可填的目標速度或避震行程問題。

這取代舊 `F_f/20`、`F_r/50` 的增量。它不會在空力缺值時生成負載；相同空力／軸重比例有相同相對剛性增量。超出上限仍回傳合法值並提示「空力目標受彈簧上限限制」，不聲稱支撐需求已完全滿足。

空力是外力，**不增加車輛慣性質量**。不把 `m+F` 拿去當成自然頻率或臨界阻尼中的質量。

## 7. 阻尼：參考既有基準，按實際彈簧變化量修正

物理阻尼係數在質量與目標阻尼比不變時，隨剛性平方根變化；來源為 `Ccrit=2√(km)`。[OptimumG Springs & Dampers Part Three](https://optimumg.com/wp-content/uploads/2020/01/SpringsDampers_Tech_Tip_3.pdf)。Forza 1–20 滑桿不是 N·s/m，本方案只將此關係用於**相對滑桿修正的工程近似**，不宣稱達到某個真實阻尼比。

定義 `Kref_i` 為既有賽事無空力參考剛性、`Rref_i` 為其回彈起點：

| 模式 | `Kref_i` | `Rref_i` | 壓縮／回彈比例 `β` |
| --- | --- | --- | --- |
| Road（含 FWD） | `Q(L_i + Δ_i × w_i, L_i, U_i)` | `1 + 19w_i` | 0.60 |
| Rally Mixed | `Q(L_i + Δ_i × w_i × 0.65, L_i, U_i)` | `1 + 14w_i` | 0.40 |
| Rally Cross | `Q(L_i + Δ_i × w_i × 0.85, L_i, U_i)` | `(1 + 14w_i) × 1.10` | 0.50 |

```text
Rebound_i = Q(Rref_i × sqrt(K_i / Kref_i), 1, 20)
Bump_i    = Q(β × Rebound_i, 1, 20)
```

使用最終合法的 `K_i`，因此修正同時涵蓋 FWD 偏置、Rally 基線改變與空力增量，不重複乘兩次。`Kref` 僅是阻尼參考，不是第二套使用者可選 solver。Road 無空力 AWD/RWD 基本維持既有阻尼；Rally 前後剛性重分配時，阻尼一起跟隨，避免把新彈簧配回完全不變的阻尼。

先限制回彈，再由實際回彈乘 β 得到壓縮，避免一邊已觸頂而另一邊仍依不可達的 raw 值計算。超限也保留診斷，不新增任意的增幅上限。

## 8. 可重播的試算結果

Subaru 參數沿用現行 `tuning_contract.rs`：1525.43 kg、前 56%、AWD；前範圍 `[3.1108587,15.556079]`，後 `[5.1341669,15.556079]` kgf/mm。此為既有測試來源，本輪沒有重新測量車輛。下表原為實作前研究試算，現已由 `chassis_load_contract.rs` 與正式 workflow 重播核對；不是新設定的遊戲量測。

| 模式／輸入 | 彈簧 前／後 kgf/mm | 回彈 前／後 | 壓縮 前／後 |
| --- | --- | --- | --- |
| Road，未填下壓力 | 10.1／9.7 | 11.6／9.4 | 7.0／5.6 |
| Road，前 100／後 150 kgf | 11.3／11.9 | 12.3／10.4 | 7.4／6.2 |
| Rally Mixed，未填下壓力 | 9.1／7.1 | 9.7／6.7 | 3.9／2.7 |
| Rally Mixed，前 100／後 150 kgf | 10.2／8.7 | 10.2／7.4 | 4.1／3.0 |
| Rally Cross，未填下壓力 | 10.8／8.5 | 10.7／7.7 | 5.4／3.9 |
| Rally Cross，前 100／後 150 kgf | 12.1／10.4 | 11.3／8.5 | 5.7／4.3 |

只填前 100＋前空力占比 40%，或只填後 150＋40%，均應等價於表中的雙軸輸入。Road 有空力時後彈簧可能較硬，是負載輸入的結果，不強制把數字調成前大後小。

本機研究腳本：`scratch/chassis-engineering-baseline-20261011.mjs`；結果：同名 `.json`。兩者位於 Git ignored 的研究區，不作為產品 SSOT 或凍結 golden fixture。

```powershell
node scratch/chassis-engineering-baseline-20261011.mjs
```

已執行 **7,875 組有效輸入**：5 種車重 × 7 種配重 × 3 種驅動 × 5 組範圍 × 3 種模式 × 5 種空力／軸重比例。檢查有限輸出、彈簧與阻尼上下限、零空力恆等、增加空力時彈簧／回彈不降低，以及相同條件下 Cross 彈簧不低於 Mixed；另核對平衡反推與窄／鎖定區間。全部通過。

這是候選算式的確定性檢查，不是量測、Rust 產品契約或性能證據。非法輸入、UI、歷史版本與真實遊戲行為仍由實作驗收涵蓋；不會用大量合成組合宣稱跨車校準已完成。

### 既有完整量測車輛補充驗證

依使用者要求，只驗證量測完整的既有配置，並以 **Road 或 Rally 至少一個合理基準** 作判定。詳見 [2026-10-11 逐車驗證](chassis-existing-vehicles-validation-20261011.md)：7 台輸入未見明顯動力矛盾的車輛、8 份正式 owner 可重播的量測，共 21 組候選模式。各車皆有合理基準，彈簧沒有依靠 clamp 才落入範圍，阻尼無飽和；無須追加車款特例或調整本計畫常數。

Beetle 一份不合格舊紀錄排除，另兩份合格仍可使用。Furai 原始量測可重播但約 627 hp／517 Nm 與車檔 458 hp／377 Nm 明顯不一致，暫不列完整配置驗收。此批只有 AWD／RWD、無提供空力，不將本次結果擴張為 FWD／有空力或新底盤實機證據。

## 9. 實作與版本決策

正式 Rust owner 為 `backend-rust/src/tuning/chassis_load.rs`。桌面使用 `tuning-workflow-result/v2` 與 `tuning-mechanical/v2`；相較 v1，`chassis` 可為 null，並新增 `chassisDiagnostics`（資格、原因、空力來源、每軸限界）。必要輸入不足時，完整底盤不回傳；baseline preview 仍保留各自合格的定位、ARB、車高與差速器，未完成補正的彈簧／阻尼不可套用。推薦同樣只納入合格欄位。

v1 API 保持原 chassis 數值與形狀，CLI／MCP 接受兩個 schema；Companion 轉送桌面的 v2 結果與診斷。傳輸 shape 與公式版本分開：Road／Rally 為 `rust/chassis-load-baseline/v1`，其他模式為 `rust/chassis-legacy/9bfd6c90`。新 recommendation 的 snapshot 由後端寫入模型與診斷；保存時依推薦版本重播並逐欄比對，不能以改標籤或偽造診斷繞過。

新草稿使用 `aeroInputVersion: optional/v1`；明確 0 與 null 分開保存。舊 Auto 0 正規化為 null，未標記的歷史平衡不升格為明確輸入。車重／配重未提供時使用缺值 sentinel 0，彈簧範圍使用 null，不再生成可被誤認為量測的 1500 kg／50%／10–120 預設。

1. **保留舊版 owner**：將目前 main `9bfd6c90` 的數值路徑保留為歷史模型入口，既有 frozen fixture 改為明確驗證舊版；不更改 fixture 預期值。新公式另建有來源案例。legacy CLI/MCP quick solver 維持自己的契約。
2. **一次建好 Rust 新模型**：純函式完成輸入資格、可選空力解析、Q、基線、空力比例、阻尼與受限診斷。僅 Road／Rally 使用新公式；其他模式委派既有路徑。先不製作 UI 模型選擇器。
3. **接入正式計算／歷史驗證**：新結果使用 `chassisModelVersion = rust/chassis-load-baseline/v1`；版本由後端選擇，不能由呼叫者任意指定。這是公式版本，不是應用程式版本。
4. **Recommendation 版本分流**：新 ICE 使用 `rust/ice-measured-workflow-v3`、新 EV 使用 `rust/ev-measured-workflow-v2`；舊 ICE v1/v2 與 EV v1 保持舊 chassis 重播，既有齒比版本語意不變。更新 `evidence.rs`／Road 驗證允許的版本及重算選擇；缺少新模型標記的歷史紀錄不可送入新公式。新 baseline preview 使用 `rust/chassis-alignment-neutral/v2`。
5. **更新草稿與 UI**：移除新模型的 Auto=0、預設 balance=0.5／取消 Auto 填 50；下壓力兩欄可留空，恰好填一軸才要求前空力占比。Rust 回傳解析來源、缺值／無效／受限原因，前端負責顯示與可套用狀態。同步純型別、CarParamsContext、defaults／normalize 與 snapshot。既有 schema 的相容性以契約測試確認；需要破壞性 shape 變更才另升 schema，不能拿 schema 代替公式版本。
6. **完成驗證與文件同步**：更新現行公式／責任契約／技能中的 Auto 空力說明；檢查三語 UI。歷史研究文件保留版本脈絡，新實作以本文件為準。

## 10. 完成條件與停止擴張的界線

實作驗收集中五組：

- **數值契約**：第 3–7 節的有效／非法輸入、空力三路徑、明確零值、單軸缺平衡、端點／溢出、窄／鎖定範圍、飽和、單位往返；上表有來源的精確數值，以及相對單調性。
- **流程契約**：修改／清空輸入後不沿用舊推導結果；不足資料時不產生可套用的完整補正；能力不因推導而解鎖；桌面、Companion、CLI／MCP 共用正式結果。
- **歷史契約**：舊 recommendation／preset／evidence 仍走對應 owner，不能以重寫 fixture 過關；新公式版本與舊齒比版本的搭配可重播。
- **既有車輛驗收**：只採量測完整且配置未見明顯衝突的資料；每個針對 Road 或 Rally 改裝的配置，至少一個賽事可得到合理基準即可，不強制所有模式通過。不完整量測或配置衝突另列，不當作公式失敗，也不猜值補齊。
- **實機基本驗收**：新公式導入後，針對上述可用配置在其適合的賽事確認遊戲可輸入、沒有明顯不可控制的彈跳或持續行程飽和。記錄固定條件與所有資料，不要求贏過最佳圈速；Mixed／Cross 比較只在同配置適用時進行。FWD、有來源空力等尚無完整實車資料的路徑保留覆蓋缺口，不為本輪驗收追加量測或用合成資料冒充。
