## 驗收層次

- **Diagnostics**：Full／Lite 都從資料根目錄讀寫 `telemetry_sessions.db`。同一資料目錄兩次啟動，透過 HTTP 保存語言後驗證 API／檔案一致；保留既有 sessions 檔案。另驗證預設／動態 HTTP port 及關閉後資源釋放。v1.7 已使用根目錄資料庫，無需遷移。
- **本地升級副本**：以正式 v1.7 Portable（11.45.20）啟動隔離的六車資料副本，再由候選 Portable（11.45.21）開啟同一目錄；語言設定、六車 profile 與 13 份歷史文件保留，原生視窗可見。這是本地執行檔替換驗收，公開 OTA 另列待驗。
- **API 錯誤**：USB、音訊與 MoTeC 操作失敗回固定 503／500；詳細錯誤留在具操作名稱的本機日誌。422 驗證訊息仍可使用，MoTeC CSV golden 保持一致。
- **EV**：`scripts/verify_ev_browser.cjs` 使用新建 Rust 程序、獨立資料根目錄與動態 port，HTTP 不 mock；只注入既有 Taycan 解碼 frames。驗證雙速、鎖定／未知齒比的單速契約、模式失效、跨頁、六種主題、繁中／英文、保存 Road workflow，關閉瀏覽器與後端再重開後比對文件與 evidence 重算結果。
- **自動測試**：Rust 全功能與 `--no-default-features`；前端 1,105 tests 通過（另有既存 1 skipped）；TypeScript 與 Windows／LAN builds；選用發行工具測試、版本一致性、Ruff 與 diff 檢查。凍結數值測試與正式 Rust 合約分開保留。

## 固定 SHA 的候選交付

合併後需針對同一個 main SHA 取得 CI／CodeQL、Host Diagnostics 與 Release Packaging Test 成功結果。Host Diagnostics 產生 `portable-candidate-<SHA>` artifact，包含 Full、Lite 與 sidecar，保留七天。Release Packaging Test 的 Linux job 產出真實 AppImage；Windows package fixture 只驗證封裝／簽章契約，不能替代 Full／Lite 執行檔驗收。

最終交付紀錄須附該 SHA、workflow run URLs、artifact SHA-256 與本地 smoke 結果；不要拿先前 PR head 或舊 `dist/` 二進位代替。

尚未追加的證據：Linux GUI 互動、不同實體主機的 LAN 遊戲傳輸、公開 OTA 實際升級、新單速 EV 車款與新 UI 遊戲內操作。這些與已完成的軟體契約／本地回放不同層級，保持標示待驗；本次使用者已接受候選驗收範圍。#462 後續較廣校準與 #435 的 EV 最佳化需求不因這些回放自動結案。

本次使用的專案技能：`portable-release-validation`、`pr-author-maintainer`、`pr-review-evaluation`、`physics-tuning-math`、`modular-refactoring`、`agent-governance-audit`、`github-security-audit`；另採用 `ponytail` 的最小實作原則。
