# FH6 空力起點：證據、邊界與驗證計畫

檢索日期：2026-09-09
範圍：只評估「可調空力時，前下壓力偏高／拉滿，後下壓力用於高速穩定、平衡與阻力取捨」是否應成為 FH6 HorizonTuner 的建議起點。本文件不是遊戲內校準、車輛通則或調校輸出；沒有改動遊戲、API 或算牌。

## 決定

值得把這個模式做成**可選的高速柏油賽起點**，但不應以 PI、馬力、車重或 drivetrain 寫成硬規則，也不應在沒有兩軸可調能力時偽造一組建議數字。

在目前證據下，安全的起點表達是：當前、後空力都可調，且使用者選擇高速彎較多的柏油賽時，先把前軸設在高端（可提供「最大前下壓力」動作），再以後軸由低往上補到高速尾部穩定；每次只改一軸並測同一路段。這是社群 meta 的候選流程，不是已由 Playground Games 公布或跨車實測的最佳解。

不要聲稱「某 PI 以上才有用」。官方已確認 FH6 的 Forza Aero 會逐車設定，且整個車輛分級已重平衡；它沒有公布前／後滑桿公式、下壓力參考速度、各車 range、PI cutoff 或 FWD/AWD 的指定比例。因此任何固定門檻都會把缺失的資料冒充為規格。

## 為何這個模式有物理合理性，但仍不是遊戲結論

下壓力隨速度上升而變得可觀，會增加輪胎法向載重，因而能改善高速彎的可用抓地；翼面或 splitter 的迎角通常也帶來阻力，減少加速與極速餘裕。前軸增加下壓力通常傾向增加 turn-in、減少高速推頭；後軸增加下壓力通常傾向提高尾部穩定、抑制高速甩尾。這些是賽車空力的一般方向，不提供 FH6 的係數或保證方向。

後翼的取捨尤其需要顯示出來：它可能補足快速彎或出彎時的後軸穩定，卻也可能以直線速度、加速或 PI 預算換取。若只看「Aero Balance」而不看效率與賽道型態，使用者可能把合理的低阻設定誤判為不足，也可能把高下壓力誤判為必然更快。

## 驅動方式與可調能力：不是同一件事

| 情況 | 可用的起點 | 必要限制 |
|---|---|---|
| FWD，前軸可調、後軸鎖定 | 可讓使用者選擇「優先前軸高速抓地」候選；實際上只調可調前軸。 | 不得顯示或儲存虛構的後軸建議，也不可將後軸鎖定誤稱為 rear-min meta。前後無法共同校正，必須提示其平衡受零件固定值限制。 |
| FWD，前後都可調 | 高前、較低後是可測的 FH5-inherited / FH6-community 起點。 | FWD 的前輪同時負責轉向、煞車與驅動，不能由 drivetrain 名稱推定後軸一定應最低；以高速推頭、尾部飄移和 terminal speed 驗證。 |
| AWD，前後都可調 | 高前、後軸從低值向上補高速穩定，是目前最常見的社群起點。 | AWD 的中心差速器、扭矩分配、胎寬、重量和路線都會改變結果；「後最小」是有用反例／候選，並非預設真理。 |
| RWD，前後都可調 | 不應套 FWD/AWD 起點；常見指南反而偏向較多後軸支撐。 | 必須獨立讓使用者選擇目的與症狀，避免將所有 drivetrains 壓成同一規則。 |

## 目前兩車觀測的正確用法

| 車輛 | 已知觀測 | 可以作為 | 不可以作為 |
|---|---|---|---|
| Integra A700 FWD，373 hp、2,913 lb、前重 57% | 前空力 207 lb、後軸鎖定；模擬空力平衡 0.64、效率 0.827。 | 「一軸鎖定」的 UI fixture：建議流程必須只處理前軸，並說明後軸不可調。 | 證明 0.64 或 0.827 是 FWD / A700 的目標，或從單次模擬證明效果。 |
| Dark Horse S1 800 AWD，832 hp、3,864 lb、前重 56%，center 90% | 前 387、後 337 lb；模擬空力平衡 0.50、效率 0.738。 | 「兩軸皆可調」的 UI fixture：可提供前高、後軸漸增測試流程。 | 證明 0.50 / 0.738 優於 Integra，或證明 90% center 分配造成這組空力數字。 |

遊戲模擬在同一車的單次讀數也可能有誤差。兩車的 PI、動力、重量、輪胎、空力範圍、drivetrain 和 track purpose 都不同，禁止將上述數字做跨車因果比較。

## UI 建議：讓使用者選擇和測量，而不是猜數字

1. 先顯示 capability：`前可調／後可調／鎖定` 與目前遊戲讀回值；只有可調軸才顯示操作或候選值。
2. 以「賽道目的」開關候選流程：`高速彎柏油`、`混合／未知`、`直線速度／Drag`、`非鋪裝`。只有第一類顯示高前、後軸由低向上補穩定的起點；其餘預設為不套用。
3. 用相對動作與後果代替裸數字：`前軸：設為最大`、`後軸：先保留目前值／逐步增加`、`預期：高速推頭減少／高速尾部更穩`、`代價：直線速度與加速可能下降`。在 lock 情況顯示「零件鎖定，無法調整」，而非 disabled number input。
4. 將 `Aero Balance` 和 `Aero Efficiency` 僅標作遊戲模擬指標，旁邊顯示當次讀取時間與「不跨車比較」說明；不要餵給自動目標或讓使用者追逐一個 magic number。
5. 套用前顯示 preview：只會改哪些軸、哪些軸因零件鎖定而不變、以及回復目前值的按鈕。候選值必須由使用者明確套用，不能 background autosave。

## 最小實測門檻（尚未完成）

對每一部候選車，以同 game build、PI、零件、輪胎、drivetrain／center diff、assist、控制器、天氣和 route 固定條件，分別做：

1. baseline（目前空力）三次有效 run；
2. 只改前軸至高端的三次有效 run；
3. 固定前軸，僅逐步增加後軸，至少各三次有效 run；
4. 記錄有效 run 的 route time、最高速度、高速彎症狀、撞擊／重試、胎滑與遊戲 build。

若 driver/traffic 誤差覆蓋差異，結論必須是 `inconclusive`。至少在另一部同類車或另一個路線重複，才可把某一方向從 `community-prior` 提升為有界的 FH6 capture evidence；即使如此也不產生通用 PI 門檻。

## 結論狀態

- **支持**：FH6 的逐車空力能力已獲官方確認；多個 FH6 社群指南都使用高前、後軸補穩定的高速柏油流程，且明確承認 drag／低速／非鋪裝是邊界。
- **反證與邊界**：同樣的社群材料也提出 AWD 後翼可省略、直線／drag 應低下壓力；FH5 的 FWD/AWD 前大後小不能視為 FH6 定律。RWD 和單軸鎖定車不能直接套用。
- **未找到**：官方的 PI 門檻、滑桿物理規格、drivetrain 公式、逐車 FH6 受控 A/B，或可支持預設自動套用的證據。
