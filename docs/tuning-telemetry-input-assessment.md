# 調校遙測輸入評估（2026-09-09）

使用者要求利用主頁 ANG／RAT 與封包內未顯示的資料，減少人工猜測。以下是資料可用性與驗證順序，不是已校準的自動調參規則。

## ANG／RAT 的來源及單位衝突

`frontend/src/features/telemetry` 下的 `TireRadar` 直接顯示逐輪 `TireSlipAngle` / `TireSlipRatio` 原值至兩位小數，沒有轉成度數或百分比。校正頁 `Step5TelemetryCalibration.tsx` 卻把 ANG 乘 `180 / Math.PI`、RAT 乘 100；MCP、詳細遙測與匯出也有各自轉換。

已找到並讀取 [FH6 官方 Data Out 文件](https://support.forza.net/hc/en-us/articles/51744149102611-Forza-Horizon-6-Data-Out-Documentation)（2026-05-15 更新；本輪於 2026-09-09 核對）。文件明確將 ANG、RAT、CombinedSlip 定義為正規化數值，與專案 packet reference 的 ANG=rad 衝突。角速度及車身姿態才分別有 rad/s、radians 單位。分析保留原始數值、符號與逐輪來源，不把 0.1 視為 10% 或實際滑移角。官方以絕對值大於 1 描述失去抓地的訊號；這不等於具體調參因果或最佳門檻。不得只改一個 consumer 而讓 JSON、binary、MCP、匯出的尺度繼續分歧。

## 輸入優先順序

| 資料 | 用途 | 限制與下一步 |
|---|---|---|
| Timestamp、車輛 ID／PI／驅動形式、圈數／時間 | 排除中斷、切車與跨場混算 | 同 PI 改裝仍需人工標記重採；計時賽不以零圈速當有效成績 |
| RPM、功率、扭力、速度、檔位及踏板輸入 | 引擎取樣、檔位使用範圍、換檔與加速片段 | 排除換檔過渡；道路量測峰值不等於穩態 dyno 曲線 |
| 逐輪 ANG／RAT／CombinedSlip | 比較彎中、制動及出彎的相對變化 | 保留原值；依驅動軸、速度及操控情境分組；不能由單一門檻直接斷言調軟 ARB 或加鎖差速器 |
| 正規化與公尺懸吊行程、車身加速度 | 比較壓縮分布及路面衝擊 | 需路段對齊、排除路肩／跳躍；高硬度不是錯誤的充分條件 |
| 胎溫、SurfaceRumble、姿態、位置 | 熱狀態與路段污染標記 | 需確認顯示單位、座標與相同路段；不能由胎溫直接反推胎壓 |
| SmashableVelDiff／SmashableMass | 標記可破壞物碰撞造成的速度損失與物體質量 | FH6 官方明確提供；需確認 parser 暴露情形，不代表涵蓋所有護欄或車輛碰撞 |
| 尚未暴露的角速度、輪速、路肩／積水欄位 | 減少姿態差分噪音、交叉檢查車輪動態、排除污染路段 | 先核實 FH6 layout 及現有 parser，再決定增補；本輪未修改 offset 或封包結構 |
| DrivingLine／AI brake 差異 | 可能協助分析 ANNA 行為 | 實際 FH6 語意與有效性尚未確認，不作自動調參輸入 |

封包未直接提供胎壓、輪胎法向載荷、摩擦係數或 slider 上下限；不能宣稱可以完全取代遊戲靜態資料。

## 首場候選的描述性比較

以基準第三場和候選第一場比較，限定有效行駛、油門 >=250、煞車／離合=0、正功率、1–6 檔：轉速中位數 6014 → 6336 RPM、功率中位數 256.99 → 269.59 kW。候選前輪正規化懸吊行程的全行駛 P95 約 0.450 / 0.409，基準為 0.704 / 0.651。候選前輪全油門 RAT 中位數約 0.215 / 0.220，基準約 0.208 / 0.212。

這是不同設定在相同事件的初步分布，不是控制全部變因的因果估計。全油門取樣比例、車速、行車路線與轉向仍有差異，下一步需要三場重複並按路段／操控階段對齊。不得把較低行程或較高功率單獨當成更佳調校。

## 六場資料的操控情境切分

分析腳本 `scratch/a700-phase-analysis.py` 讀取六份獨立記錄與已核對完賽時間，遇 race timer 重置停止。以下為各場統計再取組內三場中位數，沒有把所有幀當成獨立試驗。比較第二圈以排除起步圈；依序將 BrakeInput >40 標為制動、油門 >=250 且煞車/離合為零標為高油門，再以 |AccelerationX| >5.886 m/s² 切分高側向與低側向片段。這些只是分析分箱，不是物理調校門檻，也未做精確路段匹配。

| 指標 | 基準 | 候選 |
|---|---:|---:|
| 起跑首次達 60 km/h 的賽事時間 | 2.767 s | 2.867 s |
| 起跑首次達 100 km/h 的賽事時間 | 4.734 s | 4.817 s |
| 起跑首次達 150 km/h 的賽事時間 | 7.867 s | 7.917 s |
| 首次達 200 km/h 的賽事時間 | 25.168 s | 25.084 s |
| 第二圈高油門低側向片段 RPM 中位數 | 6101 | 6540 |
| 同片段功率中位數 | 267.13 kW | 273.83 kW |
| 第二圈制動片段，任一前輪 RAT 絕對值 >1 的幀比例 | 20.82% | 26.72% |
| 第二圈制動片段，任一前輪 ANG 絕對值 >1 的幀比例 | 16.16% | 21.98% |

表中比例是「符合條件的幀比例」，不是 RAT／ANG 的物理百分比。200 km/h 首次到達已涵蓋賽道路線與彎道，不能稱為直線 0–200 性能。制動時 ANG 與 RAT 增加，不能直接定位成外傾、差速器或 ARB 的單一原因。下一個有意義的實車變量應是基準底盤加候選齒比，或候選底盤加基準齒比；先分離動力區間改善與底盤變更的代價，再考慮單一參數微調。

## 修正範圍與實機待驗

Step 5 與 `evaluateTireTelemetryDiagnosis` 已改用明確命名的 normalized slip 契約：保留逐輪數值，依駕駛情境與驅動軸給出補採指引，移除由單幀滑移直接指定 ARB／外傾／差速器變更的高信心建議。RAT 以逐輪最大絕對值判斷，左右輪相反符號與單輪超限不會被軸平均抵消；缺少四輪有限值會顯示未就緒，不視作零滑移。未知驅動型式不預設後驅。有警訊但無具體調整時不宣稱收斂。此修正不宣稱所有既有診斷規則均已校準，懸吊／胎溫等建議仍需另外驗證。

Terra 實作、根代理檢視後補正單輪／缺資料邊界；完整前端 95 files / 643 tests 與 TypeScript / Vite build 通過，繁中 JSON 解析及 diff check 通過。Step 5 實機顯示與套用核對流程尚待完成，不以單元測試代替 UI 驗收。

歷史 session drift、詳細遙測、binary、MCP 及匯出的角度轉換尚未一起完成修正，後續需依相同官方契約處理。未新增 UDP 欄位或修改 offset。

回到目前 DEV 的調校精靈時，實機觀察為 Step 1、預設 Summer、無先前完成快照。原始碼 App 以 display 切換可見性、保留調校元件掛載，因此尚不能歸因於一般分頁切換；DEV 重載／熱更新或其他生命週期仍需重現。接續 Step 5 驗收時，必須核對實際已套用的 Forzab，而不能把重新量測的新候選視為同一組。
